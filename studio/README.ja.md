# @lines-db/studio

[English](./README.md)

Studioは[lines-db](https://github.com/toiroakr/lines-db)のブラウザ用エディタです。ローカルサーバーでJSONLのテーブルを読み込み、編集内容をスキーマで検証してから保存します。

## 起動する

Node.js 22.18.0以降が必要です。プロジェクトに両方のパッケージをインストールします。

```bash
npm install -D lines-db @lines-db/studio
npx lines-db studio ./data --open
```

既定のURLは`http://127.0.0.1:4848`です。`--port`でポートを変更し、`--port 0`で空いているポートを選べます。`--open`を指定するとブラウザが開きます。終了するにはCtrl+Cを押してください。

編集するテーブルには主キーが必要です。`id`列、またはスキーマの`primaryKey`を使い、全行に値が入っている必要があります。主キーがないテーブルは読み取り専用です。

## 編集と保存

テーブルを選ぶと、行と列を表形式で表示します。ヘッダー右端のボタンで行フォームを開くと、1件のレコードをまとめて編集できます。フォームの端をドラッグすると幅を変えられます。フォームの表示中は行をクリックして選択し、セルをダブルクリックして編集します。非表示のときは行をダブルクリックするとフォームが開きます。外部キーの入力欄から参照先の行を開けます。

行を追加するには**Add record**を使います。主キーを含む各列の入力欄があり、入力中に行全体を検証します。空の欄は行に含めず、スキーマの既定値を使います。行を選択すると削除できます。

編集・追加・削除は、**Save N changes**を押すまで未保存のままです。保存時に1つのトランザクションでまとめて書き込みます。**Discard**で未保存の変更を破棄できます。検証に失敗した場合はエラーを表示し、修正できるように変更内容を残します。通常の保存ではテーブルのJSONLファイル全体を書き直すため、編集していない行の書式も変わることがあります。

### フィールドとJSONの編集

セルの入力値は入力中に検証し、該当フィールドの下にエラーを表示します。**Set**は値を未保存の変更に加える操作です。ファイルへの保存は行いません。Enter、JSONエディタではCmd/Ctrl+Enterで値を確定できます。テキスト欄は内容に合わせて高さが変わり、Shift+Enterで改行できます。

JSONオブジェクトはキーごと、配列は要素ごとに入力欄を表示します。オブジェクトの配列は要素ごとのブロックになります。ブロックをJSONエディタに切り替えると、テキストで編集できます。構文エラーは該当位置に表示します。コメントと末尾のカンマも入力できますが、値の確定時に取り除きます。

スキーマが補った値は薄い文字で表示し、**default**の印を付けます。**Remove field**でフィールドをファイルから省略し、スキーマの既定値に戻せます。**Set null**ではnullを設定します。これらの操作はスキーマが許す場合だけ表示します。フィールドの削除、nullの設定、JSON内のキーの追加・削除を許すかどうかは、サンプル行を検証して確認します。

保存するのは、明示的に指定したフィールドと生成された主キーです。それ以外のスキーマの既定値はファイルに書きません。既定値も含めて保存するには`--write-filled-values all`を使います。詳しくは[書き戻しの挙動](https://github.com/toiroakr/lines-db/blob/main/lib/README.ja.md#スキーマが補う値)を参照してください。

### 検証エラーのある行を直す

検証エラーのあるテーブルは、元のファイルの内容を表示し、該当する行とセルに印を付けます。修正を保存すると、その行を検証して1行だけを書き換えます。他の行は変更しません。全行の検証が通ると、通常のテーブルとして読み込みます。

検証エラーが残っている間は、行を追加・削除できません。スキーマが受け付けないフィールドには**not in schema**の印を付けます。列見出しから、そのフィールドを全行で削除できます。

## スキーマを見る

**Schema**で列、外部キー、インデックスを表示します。列には型と、省略やnullの設定ができるかを示します。外部キーから参照先テーブルのスキーマを開けます。開いているスキーマは`#orders?schema=customers`のようにURLへ反映されます。

列の宣言は、スキーマのStandard Schemaの`types`から読み取ります。プロジェクトにインストールされたTypeScriptを使い、5・6ではCompiler API、7.1以降ではCorsa APIに対応しています。TypeScriptがない場合や型の宣言がない場合は、行の値から列を推論し、その旨を表示します。

**Code**タブには、ディスク上のスキーマファイルを構文ハイライト付きで表示します。検証エラーのあるテーブルではコードだけを表示します。配色はヘッダーでOSの設定・ライト・ダークから選べます。

## 共通スキーマとデータセット

スキーマとデータが別の場所にある場合は、`--schema-dir`を指定します。

```bash
npx lines-db studio seed/data/cogs --schema-dir seed/data
```

複数のディレクトリをまとめて読み込むには、`--data-dir`を繰り返します。位置引数との併用も可能です。複数ディレクトリを指定する場合は`--schema-dir`が必要です。

```bash
npx lines-db studio --data-dir seed/data --data-dir seed/data/cogs --schema-dir seed/data
```

検証、列の宣言、外部キー、Schema画面では共通スキーマを使います。一意制約と外部キーは、選んだデータセット全体で検証します。

更新・削除は各行の元のファイルへ反映します。**Add record**で保存先のディレクトリを選べます。テーブルのファイルがなければ作成します。保存途中で失敗した場合は、書き込み済みのファイルを元に戻そうとします。

## 他のツールでファイルを変更した場合

Studioはディスク上のファイルを監視します。未保存の編集がなければ変更後のデータを読み直し、編集が残っていれば通知を表示します。

保存前にスキーマの変更を確認し、変更されていれば読み直して検証します。書き込み対象のファイルが変更されていた場合は、何も書き込まずに保存を中止します。ファイル名を表示し、テーブルを読み直します。`CASCADE`や`SET NULL`などの外部キーの操作で変更されるテーブルも対象です。無関係なテーブルのファイルの変更では保存を中止しません。

## ローカルサーバー

サーバーは起動時にトークンを生成し、配信するページに渡します。ページはトークンを`sessionStorage`に保存し、APIリクエストに付けます。トークンのないリクエストには401を返します。他のサイトのページからStudioのページを読んでトークンを取得することはできません。

サーバーは自身のローカルホスト宛てのリクエストを受け付けます。書き込みはStudioのページから送られた、`application/json`のリクエストに限ります。

## コードから起動する

```js
import { startStudioServer } from '@lines-db/studio';

const studio = await startStudioServer({ dataDir: './data', port: 4848 });
console.log(studio.url);
await studio.close();
```

TypeScriptのスキーマファイルには`amaro/transform`などのローダーが必要です。CLIは自動で登録します。コードから起動する場合は、スキーマを読み込む前にローダーを登録してください。
